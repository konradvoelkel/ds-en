## Decisions and doubts

**1. `# k-Means` as the H1, "k-means" everywhere else.** The German writes *k-Means* with a
capital M in prose and headings, and *k-means* in a few places; English usage is *k-means*
throughout. I lower-cased it in all prose and in every section heading (`## One k-means
iteration`, `## k-means in scikit-learn`, `## Where k-means reaches its limits`) but left the
H1 as `# k-Means`, because `statistical-models.md` is already translated and links this
chapter as `[k-Means](kmeans.ipynb)`, and `descriptive-statistics.md` links it as
`[clustering by k-means](kmeans.ipynb)`. Keeping the H1 is what makes both of those correct
at once. If a consistency pass would rather have `# k-means`, the link text in
`statistical-models.md` has to move with it – the two files cannot be decided separately.
Derived forms follow the lower-case rule: `3-means`, `2-means`, `%s-means`, including inside
the plot titles, where the German cell 34 had `3-Means`.

**2. *Hauptachsentransformation* → "principal component analysis" (block `c29.2`).** The
chapter's Trivia bullet ends "Wieder ein Grund mehr, um Hauptachsentransformation zu lernen",
pointing at `dimensionality-reduction.ipynb`. The literal "principal axis transformation"
exists in English but names the linear-algebra operation, not the data-analysis method the
reader is being sent to; and the glossary already fixes *Hauptkomponentenanalyse* →
principal component analysis. `eda-examples.ipynb` glosses the German word itself as
"(principal component analysis, PCA)", so the book treats the two as one thing. I used
"principal component analysis". The cost is that the German's three names (*PCA*,
*Hauptkomponentenanalyse*, *Hauptachsentransformation*) collapse to one in English; a reader
of the German edition who notices the word is no longer being varied loses nothing but the
variation. `kernel-methods.ipynb` has the same word and will have to make the same call.

**3. Cross-reference link texts, three of which point at chapters not yet translated.** The
German link texts are short names, not full chapter titles, so I translated the names and
took the English from the glossary rather than from the (still German) H1s:

| German | English used here | target's state |
|---|---|---|
| `[Titanic EDA]` | **[Titanic EDA]** | translated; H1 is *Titanic EDA, a first pass* – the short name matches what `descriptive-statistics.md` already uses |
| `[Kernel-Methoden]` | **[Kernel methods]** | `kernel-methods.ipynb` still German; glossary row *Kernel-Methoden → kernel methods* |
| `[Dimensionsreduktion]` | **[Dimensionality reduction]** | still German; `multivariate-normal.ipynb` already uses this exact link text |
| `[Expectation-Maximization]` | **[Expectation-Maximization]** | already English in the German; hyphen kept, because the German keeps it *in this block* while the table in `c1.4` and the bullet in `c1.2` write it unhyphenated – the German's own inconsistency, preserved |

The chapter also names four chapters in running prose without linking them (`c1.2`, `c1.3`,
`c1.4`): *Dimensionsreduktion*, *Expectation Maximization*, *Modell-Auswahl*,
*Kernel-Methoden*, *Regressionsanalyse*. I used the glossary terms with an initial capital
("the chapter Dimensionality reduction", "Model selection, Kernel methods", "Regression
analysis"), i.e. treated them as chapter names, not as topics. Once those five chapters have
English H1s, a consistency pass should check these five bare names against them – especially
*Regressionsanalyse*, whose file is `linear-regression.ipynb` and which other translated
chapters have already called both *Regression analysis* and *Linear regression*.

Four smaller calls, for the record:

* **"Nicht ein einziger" vs. the Titanic number.** Block `c3.0` reads "die Regel ‚Frauen
  überleben' auf der Titanic kam auf $0{,}79$". I added one word – "only reached $0.79$" –
  because German's bare "kam auf" carries the comparison by position and English does not.
  It is an intensifier the original does not have; drop it if a style pass objects.
* **German quotation marks and dashes.** `„Frauen überleben"` → `"women survive"`; the paper
  title in `c29.2`, which the German sets in curly single quotes (`'How slow is the k-means
  method?'`), is now in plain double quotes, both because of `TRANSLATION.md` §6 and because
  `check_english.py` flags `'` as a German quote mark. Four em dashes (`—`, in blocks
  `c33.1`, `c33.3` twice, `c33.4` and `c35.0`) became spaced en dashes.
* **`<!-- [kmeans-in-action.mp4](kmeans-in-action.mp4) -->`** – block `c13.0` is an HTML
  comment holding a dead link to a video file that is not in the repository. It is invisible
  to the reader and I left it byte-for-byte as it is, rather than dropping the block: a drop
  needs a reason better than "it is commented out", and `tools/segment.py` counts it as a
  block either way. Worth a human decision.
* **The `'optimale' $k$` quotes.** The German uses single quotes for scare quotes around
  *optimale* (`c4.0`), *Zentroide* (`c5.0`) and *reparieren* (cell 10's comment). English
  usually prefers double quotes for that, but single quotes inside a notebook that also uses
  `'...'` for Python strings are less confusing, and `TRANSLATION.md` §6 only legislates the
  German-shaped marks. Left as single quotes.
